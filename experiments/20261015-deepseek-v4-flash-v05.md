## 未通过任务失败原因（10 题，含失败链）

失败 case 均已生成四节可视化（作者路径 / Agent 实际路线 / 对照表 / 合法替代路径），详见 `visualization/`。

**一、收尾执行失败（信息已到手，差临门一脚）——3 题**

- **DSB-13**（FR1/FR4）：摘要要素全对（Garden 12 Ramp Lane / 13:30 / 247.80 / verify-F101），只差一次 `reserve_table entry=r101-v2`。失败链：未重查目录、错过 7-10 10:00 报价翻新（r101-v1→v2）→ 过早锁定 Harbor r106 两次提交被拒 → 拿到 Klein 批准后陷入查询死循环至 7-11 16:00 截止 → 误判 not_feasible。
- **DSB-15**（结论+表单）：judge 6/6 全过。步 23 重查已见 charge-photo-final，步 25 仍提交旧条目 charge-photo → 恰在截止时刻被拒 → 重提交无时间办结 → 诚实提交 unconfirmed（应为 contained_and_disputed）。
- **DSB-21**（结论+表单）：judge 6/6 全过。首次 dispatch 表单 return_address 不在 expect 白名单被拒 → 从未回表单页看拒件结论、5 次扑空查不存在的记录 → 修正包两次提交到 xlc_dispatch_desk 而非 redispatch desk → 无任何回执 → unconfirmed（应为 delivered）。

**二、时机 / 等待管理失败——3 题**

- **DSB-06**（W-R2）：工程师诊断复函（G-42 密封圈）未到时于 11-18 17:00 提前提交，summary 自认"配件名称尚未书面确认"→ 锚点缺 G-42。
- **DSB-23**（XPT-R2/R4）：陪护邮件发于列车延误公布前，仅获受理回执；延误事件发布后整个 04-17 空转未重发 Lea 请求；04-18 距截止 1 小时才补发（无回信）；**全程从未调用 stay_book** → unconfirmed（应为 stay_booked）。任务实为可解（villa 全天在架、补发即可走通）。
- **DSB-16**（结论）：judge 5/5 全过、表单全办结。learning_records 中 assessed portfolio-packet 行已出现，但 career_dialogue 两次提问未含 approve 字眼，persona 按回退规则答"尚未完成"→ agent 把谨慎话术当权威否决 → 从未调用 apply_desk → 空等至 02-12 截止提交 unconfirmed。

**三、结论标签 / 诚实性失分——1 题**

- **DSB-04**（L-R5/L-R6）：四项事实子目标全达成、陷阱全躲开。书面回执只说"完成 7 天校准后最早可用 11-25 13:00"，agent 却在总结追加"校准已完成"并误选 available_now（应为 available_after_calibration）→ 结论+诚实性双失。

**四、字段语义误读——1 题**

- **DSB-18**（XGC-R2）：notice_delivery_form 的 content 字段 expect 为范围声明（"required action and deadline only"），agent 4 次都填消息原文全被拒，陷入"重访 FAQ 页+同字段重试"死循环（步 59-74）。次级：未先书面核实就提交初始申请被退回、一周无效轮询，把交付拖到截止日当天。

**五、疑似评分端 / 机制 errata（建议复核，不计入 Agent 真实失败）——2 题**

- **DSB-10**：judge 6/6 全过、结论正确、表单办结、陷阱全躲开。唯一失败是确定性锚点把 goal 值中的时区偏移 `+08:00` 抽成字面 token "08"，agent 写"北京时间"无字面对应 → judge_denied。属锚点抽取口径问题，建议 regrade errata。附带效率问题：关键词 "CAM-402" 查验机状态 4 次皆空，不带关键词才取得回执。
- **DSB-31**（GOV-R4）：4/5 过、结论正确。Rosa 的 LLM dialogue persona 对电话问题答"无法凭记忆核实"，authored phone 关键词规则（"555-0182"）疑似未触发 → agent 11 次电话追问死循环拿不到号码 → 表单因电话不匹配仅 processed → 回执 RELIEF-11822-R1 未生成、总结缺三要素。疑似 persona 规则注入与 authored 规则不一致，建议按勘误流程复核模拟器。

## 备注

- 隐藏工具发现在 10 个失败 case 中基本无问题（多数 case 三个隐藏工具全发现）；v0.3 时代占 37.5% 的"证据引用粗心"类随引证制取消而消失，失败重心移向执行环节。

- 每题 final_answer.json / rpc_trace.jsonl / result.json 提供答案、交互与逐项目标判定；agent_calls.jsonl 与 simulator_calls.jsonl 记录 API 调用与 usage。
